## 一、为什么排除掉其它路线（决策依据）

| 路线 | 结论 | 原因 |
|---|---|---|
| 即梦官方 CLI | ❌ 不可用 | **仅高级会员可调用，本机是标准会员** |
| CDP 接管端口 | ❌ 不够用 | 能操作网页 DOM，但**够不到原生文件对话框**（不在渲染树里） |
| JS / DOM 注入设置 file input | ⚠️ 部分可用 | `DOM.setFileInputFiles` 理论可行（见旧 `jm_upload.py`），但它依赖 CDP 端口，与「不接管端口」的要求冲突，且页面改版易失效 |
| **纯人手模拟** | ✅ **选定** | 与 UI 实现完全解耦，浏览器/网页怎么改都能用；唯一门槛是坐标标定 |

**最终方案的价值**：因为不依赖任何内部接口，即梦前端怎么改版都不影响——只有坐标需要重新标定。

## 二、★ 核心技术验证：原生文件对话框能否被纯键盘接管

这是整个方案成立与否的关键。**已实测通过。**

测试方法：用 `comdlg32.GetOpenFileNameW` 弹出一个与即梦上传**完全相同类型**的原生对话框（窗口类 `#32770`），标题设为「测试-选择参考图」，然后：

4. `Enter` 确认


**结论**：`点「+」→ 等 #32770 → 粘贴完整路径 → 回车` 这条链路**完全可行**，是稳定且与 UI 布局无关的解法。

## 三、环境依赖坑

### 1. DPI 缩放必须最先处理

用户屏幕 **3840×2160 物理 / 150% 缩放**，逻辑分辨率 **2560×1440**。

- 进程若不声明 DPI aware，`pyautogui.size()` 返回的一类坐标会和实际观察值差 1.5 倍，点击全部偏移。
- **必须在 `import pyautogui` 之前**调用：

```python
import ctypes
ctypes.windll.shcore.SetProcessDpiAwareness(2)   # PER_MONITOR_AWARE_V2
```

- 验证：设置后 `pyautogui.size()` 应返回 `3840x2160`（物理），而截图坐标按此换算。

### 2. pyautogui 的 FAILSAFE 会坑人

默认 `FAILSAFE=True`：鼠标一旦移到屏幕四角就抛异常中断。自动化跑起来容易误触。
**设为 `False`**，改用显式坐标校验来保安全。

### 3. 依赖安装（本机实测）

本机 pip 走清华源时 **pyautogui 找不到可用版本**（Python 3.13 无匹配 wheel），换**阿里云源**成功：

```bash
pip install pyautogui pyperclip pywinauto pillow -i https://mirrors.aliyun.com/pypi/simple/
pip install opencv-python numpy -i https://mirrors.aliyun.com/pypi/simple/
```

> 另一处已知本机问题：npm 官方 registry 会 502，npm 装包走 `--registry=https://registry.npmmirror.com`。（与本技能无关，记录备查）

### 4. pywinauto 打印控件树的方法名

`Desktop(backend="win32").windows()` 返回的是 `DialogWrapper`，**没有** `print_control_identifiers`。
枚举窗口用 `.class_name()` / `.window_text()` / `.is_visible()`；要打控件树得先 `.wrapper_object()`。

### 5. 记事本不适合做对话框测试

Win11 记事本是 Store 应用，「另存为」用的**不是** `#32770`。测原生对话框请在代码里直接调 `GetOpenFileNameW`（本技能的做法）。

## 四、即梦网页操作坑

### 1. 中文提示词必须走剪贴板

`pyautogui.write()` 只能打 ASCII。中文/emoji 一律：

```python
pyperclip.copy(text); pyautogui.hotkey("ctrl", "v")
```

### 2. React SPA 不认代码赋值

直接 `element.value = "xxx"` 不触发框架状态。必须发**受信任的真实键盘事件**——这正是人手模拟路线的天然优势。

### 3. 上传后不要去找文件图标点

原生对话框默认停在「下载」文件夹，里面文件极多：
- 文件名含中文会被省略号截断（截图里 34 个条目几乎全带 `...`）
- 按时间分组（昨天/本周早些时候/上月），位置不固定
- 网格会滚动，图标坐标不稳定

**唯一稳定解**：文件名框粘贴完整绝对路径。

### 4. 文件名框可能有残留

粘贴前必须先 `Ctrl+A` 全选，否则会拼接到已有内容后面。

### 5. 上传真人脸部图会被拦

平台合规限制，写实真人脸素材会被自动拦截导致无法生成。换非写实素材。

### 6. 首尾帧模式的提示词不能省

不写提示词有概率得到"叠化过渡"（俗套的淡入淡出）。要写清楚**主体 / 场景 / 过渡方式**，成功率显著提升。

## 五、⛔ 铁律（沿用既有约定）

**Agent 绝不重启 / taskkill / Stop-Process 用户的浏览器。**

重启拿到的是**没有登录态**的实例（`--user-data-dir` 并不会如预期复用登录态）。接管必须基于**用户自己手动打开且已登录**的窗口；连不上时的正确动作是**停下来请用户确认登录**，不能代劳杀进程重启。

## 七、★ 坐标标定实录（2026-10-09 实测）

### 遇到的第一个问题：截图里根本不是即梦

用户给的局部截图（504×357）只包含了浏览器标签栏和标题，看不到主体。
我自己截全屏后发现：**屏幕上显示的是抖音全屏播放页**，即梦在 Edge 的**另一个标签页**里。

教训：截屏前先确认目标页面**在前台可见**。窗口标题里的"和另外 6 个页面"就暗示了多标签状态。

### 第二个问题：视觉模型直接标坐标误差很大

把全屏降采样成 1500×843 让模型标，它给的结果**自相矛盾**：
- "上传参考图"标在 (580, 220)，"主输入框"标在 (850, 220) —— 但加号明明在输入框**左上角**，不可能同高
- "发送按钮"标在 (1105, 262)，与技能标签行同 y —— 也不对

**降采样丢失细节 → 模型只能靠语义猜，坐标不可用。**

### 解法：裁剪放大 + 准星自检

1. **裁剪放大**：把输入框区域（物理 x:1250-3300, y:420-780）原分辨率裁出来放大 3 倍
   → 等效分辨率提高 3 倍，模型在小图里能看清加号笔画
2. **换算**：`物理 = 裁剪原点 + 图内坐标 / 放大倍数`
3. **★ 准星自检**：在候选坐标画红十字+蓝横线，让模型回答"交点落在什么元素上"

实测对比（这一步的价值）：

| 元素 | 模型初标 | 准星检查结果 | 修正后 |
|---|---|---|---|
| 上传加号 | (1490, 570) | ❌ "什么都没有，偏右偏下" | **(1491, 570)** 裁剪放大重标后 ✓正中 |
| 主输入框 | (2000, 560) | ❌ "深色背景什么都没有" | **(1725, 605)** 换用"框内空白点" ✓ |
| 发送按钮 | (2860, 673) | ✅ "距离圆心偏 3-4px" | **(2860, 673)** 直接可用 |
| Agent标签 | (1537, 673) | ✅ "落在字母 t 上" | **(1537, 673)** 直接可用 |

**结论：不加准星自检，就会把差 40px 的坐标当正确的用。**

### 最终实测坐标（物理 3840×2160）

| 元素 | 物理坐标 | 基准坐标(÷1.5) |
|---|---|---|
| 上传加号 `upload_plus` | **(1491, 570)** | (994, 380) |
| 输入框空白点 `prompt_box` | **(1725, 605)** | (1150, 403) |
| 发送按钮 `send_btn` | **(2860, 673)** | (1907, 449) |

### 页面结构实测

- 浏览器标签栏：y ≈ 8–62；想在哪个标签就用 `TabItem` 枚举拿坐标
- 地址栏：y ≈ 65–112

### ★ 安全坑：切标签页前必须校验前台窗口

用户当时**抖音窗口盖在最上面**。如果脚本直接点标签坐标，会点到抖音上。

正确流程：
```
1. 枚举 TabItem 找即梦标签坐标
2. ShowWindow + SetForegroundWindow 把 Edge 拉前台

4. 校验通过才点击
```
已封装为 `jm_video_human.py` 的 `switch_to_tab()`。

### ★ 实操中发现的第一个坑：窗口尺寸变化导致坐标全废

- **上午标定时**：Edge 最大化，rect `(-11,-11,3851,2099)`，加号物理 `(1491, 570)`

```python
PLUS_OFFSET = (599, 569)   # = 加号坐标 - 窗口左上角
实际加号 = (rect.left + PLUS_OFFSET[0], rect.top + PLUS_OFFSET[1])
```

### ★ 新安全规则：操作前检测用户空闲

人手模拟会抢鼠标。用户正在用电脑时操作 = 互相干扰 + 坐标作废。

**长流程中每一步操作前都应调用**，空闲不足 30 秒就暂停或询问用户。

### ★ 发送按钮：用户确认 + 图像识别法（比坐标更稳）

用户明确告知：**白色圆底 + 黑色向上箭头 = 输入确认键，点一下即可**。

实测像素特征：
- 白圆环带平均亮度 **~169–247**，页面深色背景仅 **~22** → 对比度极高
- 输入框**有内容**时按钮为白圆（激活）；**为空**时为灰圆（禁用，点了没反应）

定位算法（`jm_video_human.find_white_circles`）：
```
灰度阈值 >140 二值化 → 连通域分析 → 过滤：
  面积 600~20000、包围盒近正方形(0.75~1.33)、圆形度 fill=area/(w*h) 0.6~0.95、亮度>140
```
验证：
- 用户截图（996×411）：白圆精确定位 **(871, 188) r=24** ✅
