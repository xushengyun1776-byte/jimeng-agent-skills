# 即梦网页 · 参考图生视频（纯人手模拟）

## 这个技能解决什么

在即梦网页版上传参考图生成视频。**全程模拟真人鼠标键盘操作**，不使用任何自动化接口：

- ❌ 不接管浏览器调试端口（CDP / 9222）
- ❌ 不使用即梦官方 CLI（**标准会员无调用权限，只有高级会员可用**）
- ❌ 不注入 DOM 脚本（原生文件对话框在渲染树外，注入也够不到）
- ✅ 只做三件事：**真实鼠标移动点击、真实键盘按键、剪贴板粘贴**

## 为什么必须是"人手模拟"

即梦网页有三个绕不开的硬约束，决定了只有人手模拟这条路能走通：

| 约束 | 说明 |
|---|---|
| **没有 API 权限** | 即梦 CLI/API 仅高会员开放，标准会员调不了。网页是唯一入口。 |
| **上传走原生对话框** | 点「+」后弹的是 **Windows 原生 `GetOpenFileNameW` 对话框（窗口类 `#32770`）**，它**不在浏览器 DOM / 渲染树里**。CDP、JS 注入、selenium 的 `send_keys` 全都够不到它。 |
| **React SPA 不理代码赋值** | 直接改 `input.value` 不触发框架状态，必须发受信任的真实键盘事件。 |

> 已实测确认：原生文件对话框可被**纯键盘完整接管**（往「文件名」框粘贴完整路径 → 回车），中文路径无障碍。详见 `references/踩坑记录.md`。

## 前置条件

```bash
pip install pyautogui pyperclip pywinauto pillow opencv-python numpy
```

- **浏览器**：Chrome 或 Edge（Safari 不支持图生视频实时预览）。手动打开、手动登录即梦。
- **⛔ 铁律**：**绝不重启 / taskkill 用户的浏览器。** 接管只针对用户自己开好并已登录的窗口。
- 屏幕缩放 150% 时进程必须先声明 DPI aware，否则坐标全错（脚本已内置）。

### 步骤 1 · 打开即梦创作页

浏览器访问 `https://jimeng.jianying.com/ai-tool/home/`，确认已登录。
页面为居中布局：标题「你好，今天想要创作什么？」→ 模式胶囊（生成/画布）→ 主输入框 → 技能标签行。

对应截图：`references/screenshots/step1-即梦首页上传入口.png`

**★ 确保即梦标签页在前面**（实操踩过的坑）：用户往往开着很多标签页，
而且可能有**另一个窗口盖在最上面**（如抖音全屏窗口）。此时直接点坐标会点到别的程序。

正确做法：**先枚举标签页拿到即梦那个的坐标，再校验前台窗口，最后才点**：

```python
# 1) 枚举 Edge 标签页找即梦（pywinauto uia）
for d in Desktop(backend="uia").window(handle=edge_hwnd).descendants(control_type="TabItem"):
    print(d.window_text(), d.rectangle())   # 找到标题含"即梦"的那个

# 2) 把 Edge 拉前台 + 校验（否则可能点错窗口）
win32gui.ShowWindow(EDGE_HWND, win32con.SW_RESTORE)
win32gui.SetForegroundWindow(EDGE_HWND)
assert win32gui.GetForegroundWindow() == EDGE_HWND, "Edge 未在前台，中止！"

# 3) 点即梦标签页
pyautogui.click(*TAB_COORD)
```

实测数据：Edge 窗口 7 个标签，即梦在索引 `[5]`，标签中心物理坐标 `(2033, 31)`。
浏览器标签栏 y≈8–62，地址栏 y≈65–112，网页内容 y≈185 起。

> **安全铁律**：点击前必须校验前台窗口。否则鼠标会点到用户当前正在用的其它程序上——
> 这是人手模拟最大的风险来源。见 `jm_video_human.py` 的 `focus_window()`。

### 步骤 4 · ★★ 接管原生文件对话框（核心难点）

对应截图：`references/screenshots/step3-原生文件选择对话框.jpg`

对话框是标准 Windows 原生选择器，默认停在「下载」文件夹。**不要试图去找文件图标点它**——文件名会被省略号截断、列表还会滚动，极不稳定。正确做法是**直接用完整路径**：

```
1. 等对话框出现（轮询窗口类 #32770）
2. Ctrl+A 全选「文件名」输入框
3. 剪贴板粘贴【参考图的完整绝对路径】
4. 回车（等价于点「打开」）
```

脚本已封装：

```python
from jm_video_human import fill_dialog_path
fill_dialog_path(r"<参考图目录>\参考图.png")
```

或命令行调试：

```bash
python scripts/jm_video_human.py dialog "E:\路径\参考图.png"
```

**为什么用路径而不是点文件**：文件名含中文+省略号、图标网格会滚动、不同分组（昨天/本周/上月）位置不固定。粘贴完整路径是唯一与 UI 布局无关的稳定解法。

**★ 2026-10-09 实操验证的完整提交流程**（Agent 模式下）：

```
1. 点输入框内空白 (2044, 560)      # 已验证在框内
2. Ctrl+V 粘贴提示词
3. 点发送按钮 (2862, 674)          # 准星验证偏差 ~1.6px
```

### 步骤 7 · ★ 点发送（图像识别法，不靠坐标）

用户确认：**输入框右下角「白色圆底 + 黑色向上箭头」= 发送确认键**。

关键特性（实测）：
- 输入框**有内容** → 按钮是**白圆**（激活态，亮度 ~247）→ 可点
- 输入框**为空** → 按钮是**灰圆**（禁用态）→ 点了没反应

所以**"找到白圆"本身就是发送就绪的安全联锁**：找到才点，找不到说明状态不对。
白圆在深色页面上对比度极高（背景亮度仅 ~22），用
**亮度阈值 + 连通域 + 圆形度**定位，窗口移动/缩放/改版都不怕：

```python
from jm_video_human import click_send
click_send()          # 自动找白圆并点击；找不到不点，返回 False
```

或命令行只找不点（自检）：

```bash
python scripts/jm_video_human.py findsend
```

> 坐标法（`(2862, 674)`）仍保留作兜底，但**优先用图像法**。
> 实测：用户截图中白圆被精确定位 `(871, 188) r=24`；输入框为空时全屏**零候选**——
> 正好验证了"白圆=激活态"的联锁逻辑。

发送后页面跳转 `/ai-tool/generate?workspace=...`，状态序列：
「再思考片刻...」→ 进度百分比（如 50%）→ 出图（实测约 35 秒 / 2 张 / 16 积分）。

轮询判定：截屏问视觉模型"对话区是否已出现渲染完成的结果图"，
回答 DONE / WAIT / ERR 三态循环，DONE 即截图取图。

**★ 下载环节实测坑（2026-10-09）**：

1. **结果图上的悬浮工具条（下载↓/更多/收藏）只在鼠标悬停时出现**，
   且**悬停后截图里工具条可能已消失**（截图时机问题）→ 点击容易落空。
2. 点悬浮下载键后 **Downloads 无新增文件、无下载栏、无 toast** —— 点击未生效。
3. **更稳的取图方式：直接从全屏截图裁结果图**（本次即用此法交付 2 张图）。
   结果图在页面上的物理位置可用视觉模型标定后按中心±边距裁剪。
4. 若必须下高清原图：先**双击结果图打开查看器**，查看器内下载键是常驻的
   （旧技能 `jimeng-web-automation` 的「向下箭头=下载键」经验适用于查看器，
   下载落盘 `<下载目录>/jimeng-<日期>-*.png`）。

**★ 安全规则：操作前检测用户空闲**

人手模拟会抢鼠标。**用户正在用电脑时不要操作**。检测空闲：

```python
import ctypes
class LASTINPUTINFO(ctypes.Structure):
    _fields_ = [("cbSize", ctypes.c_uint), ("dwTime", ctypes.c_uint)]
lii = LASTINPUTINFO(); lii.cbSize = ctypes.sizeof(lii)
ctypes.windll.user32.GetLastInputInfo(ctypes.byref(lii))
idle_s = (ctypes.windll.kernel32.GetTickCount() - lii.dwTime) / 1000
# idle_s < 30 视为用户活跃，应暂停或询问
```

本次实操中因用户中途动了鼠标/窗口（Edge 被最大化、页面被导航到搜索页），
导致后续下载点击落空。**长流程中每一步操作前都应重新校验页面状态**。

## 关键坐标锚点（★ 已实测标定，非估算）

### ⚠️ 首要认知：坐标随窗口尺寸变化，必须每次现标

2026-10-09 实测中发现：同一台电脑上，
- 第一次标定时 Edge 是**最大化**（rect `(-11,-11,3851,2099)`），加号在物理 `(1491, 570)`
- 第二次实操时 Edge 变成**普通窗口**（rect `(891,0,3075,2088)`），加号在物理 `(1490, 569)`

**窗口尺寸变了，绝对坐标会全部失效。** 所以：
1. **优先用相对窗口的偏移量**（脚本已实现：`PLUS_OFFSET = 加号 - 窗口左上角`）
2. 窗口几何每次运行时**动态读取** `GetWindowRect()`
3. 绝对坐标只作兜底

### 实测坐标（Edge 最大化时，物理 3840×2160）

| 锚点 | 物理坐标 | 验证状态 |
|---|---|---|
| `upload_plus` | **(1490, 569)** | ✅ 准星验证偏差 4-6px，实操点击成功弹出对话框 |
| `prompt_box` | (1725, 605) | ✅ 落在输入框内空白处 |
| `send_btn` | (2860, 673) | ✅ 距圆心偏差 < 4px |
| `agent_tag` | (1537, 673) | ✅ 落在「Agent 模式」文字上 |

> 基准坐标 = 物理 / 1.5（150% 缩放）

### 加号相对窗口的偏移（★ 推荐用法）

```
PLUS_OFFSET = (599, 569)   # 加号坐标 - Edge窗口左上角
实际加号 = (rect.left + 599, rect.top + 569)
```

### 标定方法（可复用）

不靠猜，用这套**准星自检法**标定任何 UI 元素：

1. 全屏截图 → 裁剪目标区域 → **放大 2–6 倍**（等效提高分辨率，精度可达 ±5px）
2. 让视觉模型在**裁剪图坐标系**里给出元素中心坐标
3. 按 `物理 = 裁剪原点 + 图内坐标 / 放大倍数` 换算回物理坐标
4. **画十字准星再截一次图**，让模型确认准星是否正落在目标元素上
5. 若偏移，按模型报的偏移量修正后重测

> 第 4 步是关键。省掉它就会踩「模型给了个看似合理但差 40px 的坐标」的坑。
> 实测中模型初标「上传加号」偏差约 40px；放大 6 倍重标后准星确认偏差仅 4-6px。
>
> **放大倍数越高越准**：放大 3 倍时模型仍会标偏，放大 6 倍后才精确命中。

## 常见问题

| 现象 | 原因 | 解法 |
|---|---|---|
| 点击位置偏移 | 进程未声明 DPI aware，150% 缩放下坐标缩了一半 | 脚本已内置 `enable_dpi_awareness()`；自己写脚本务必先调 |
| **点击完全落空** | **窗口尺寸变了**（最大化↔普通窗口），绝对坐标失效 | **用相对窗口偏移量**，或重新标定 |
| 鼠标被甩到屏幕角落后中断 | pyautogui 的 FAILSAFE 触发 | 已设 `FAILSAFE=False`；自写脚本注意 |
| 中文提示词输不进去 | `pyautogui.write` 不支持非 ASCII | 走剪贴板：`pyperclip.copy` + `Ctrl+V` |
| 原生对话框等不到 | 点击没落在「+」上 / 浏览器弹窗被拦 | 先截图核对位置，确认点中加号卡片 |
| 对话框填完没反应 | 文件名框有残留内容 | 必须先 `Ctrl+A` 全选再粘贴 |
| 上传真人脸部图被拦 | 平台合规 | 换非写实人脸素材 |
| **上传后缩略图不出现** | 素材审核中，需等几秒 | 正常现象。页面会先显示「素材审核中...」，数秒后转正常 |
| **点错到别的程序上** | 目标窗口不在前台 | 点击前**必须校验 `GetForegroundWindow() == 目标hwnd`** |
